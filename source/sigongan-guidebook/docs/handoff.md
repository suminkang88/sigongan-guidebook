## 1. 프로젝트 개요

### 목적

시공간의 웹 접근성 가이드북을 검색·탐색·참조하기 쉬운 문서형 웹사이트로 구현한다. 읽는 사람이 개념을 이해한 뒤 업무별 점검과 수정에 적용할 수 있어야 한다. Vercel에 배포할 수 있는 정적 사이트를 기본으로 한다.

### 대상 사용자

- 기업의 웹·콘텐츠·ESG 담당자
- 디자이너·기획자·개발자
- 쇼핑몰·공공기관·금융 서비스 운영자
- 키보드·스크린리더·화면 확대 등 다양한 방식으로 문서를 이용하는 독자

‘에이택이 발행하는 회사 가이드’처럼 회사와 서비스의 관계를 뒤바꾸지 않는다. 영문 표기·성능 수치·전문가 검수의 실제 제공 범위는 추측하지 않는다. AI와 사람 검수의 결합은 본문에서 권장 절차로 설명하며, 검증 없이 실제 상품 기능으로 단정하지 않는다.

### 레퍼런스와 우선순위

1. 사용자가 직접 지정한 시공간 홈페이지: https://sigongan.com/ko
2. 접근성 기준: KWCAG 2.2 및 WCAG 2.2 A·AA를 각각 점검
3. 문서 탐색 구조 참고: Apple HIG https://developer.apple.com/design/human-interface-guidelines
4. 글의 어조 참고: 삼성 70, 토스 30. 단정하고 정확한 ‘~합니다’체에 쉬운 예시를 결합한다.

시공간의 시각적 정체성을 유지하면서 문서 탐색은 HIG처럼 구성한다. 아래 치수·UI 동작은 가이드북을 위해 확정한 설계값이며, 레퍼런스의 모든 수치를 그대로 복제한 것은 아니다.

## 4. 콘텐츠 처리와 편집 규칙

### 입력 파일 처리

`접근성_가이드북_노션용_1차문안.md`를 정본으로 사용한다. 6개 장을 각각의 MDX로 분리하고 다음 원칙을 지킨다.

- 최상단 ‘웹 접근성 실무 가이드’와 각 장의 H1은 페이지 메타데이터로 이동한다. 렌더링되는 페이지에는 H1이 하나만 있어야 한다.
- 본문의 H2·H3 계층과 문단·표·예시·FAQ·체크리스트·출처를 보존한다.
- ‘편집 검토 메모 — 발행 본문 제외’는 렌더링·검색·RSS·사이트맵의 본문 대상에서 제외한다.
- ‘공통 발행 점검’은 내부 검수 기준으로 옮긴다. 독자에게 공개할 체크리스트와 혼동하지 않는다.
- 본문을 카드 제목만 남기는 수준으로 축약하지 않는다.
- 색상·장식 때문에 문서의 읽기 순서나 의미를 바꾸지 않는다.
- 문안의 기준 확인일은 원본 날짜를 유지한다. 빌드한 날짜로 법령 검증일을 자동 갱신하지 않는다.

### 출처와 정확성

법적 의무·인증기관별 조건·실무 권장사항을 구분한다. 가상 예시 표기를 유지하고, 법령·가격·통계를 임의로 최신화하지 않는다. 출처 URL과 확인일을 meta 데이터와 본문에 보존한다. 서비스 성과 수치를 새로 만들지 않는다.

### 콘텐츠 스키마

아래는 논리 구조 예시다. 실제 Astro API는 설치한 안정 버전의 공식 문서에 맞게 구현한다.

```ts
type GuideMeta = {
  key: string;
  title: string;
  description: string;
  order: number;
  category: 'basics' | 'content' | 'operations';
  route: string;

```

섹션 ID·제목에서 현재 장 목차를 생성하고, 그룹·페이지 순서는 단일 navigation 데이터에서 관리한다. 본문 MDX와 경로 설정이 어긋나면 빌드 또는 검증 단계에서 실패하도록 한다.

Do/Don’t 색상은 가이드북을 위해 추가한 의미 색상이다. 레퍼런스의 실제 토큰으로 소개하지 않는다. 라벨과 테두리·아이콘을 함께 써 색상만으로 구분하지 않는다.

### 5-2. 대비 확인값

WCAG 상대휘도 공식으로 아래 단색 조합을 계산했다. 실제 렌더링·투명도·hover·disabled·강조 구문의 모든 조합까지 검증된 상태는 아니다.

| 전경 / 배경 | 계산 대비 | 적용 |
| --- | --- | --- |
| `#0B4A8A` / `#FFFFFF` | 약 8.90:1 | 링크 또는 반전된 주 버튼 |
| `#0B4A8A` / `#EAF1F9` | 약 7.81:1 | 선택 상태·요약 |
| `#3C4250` / `#FFFFFF` | 약 10.06:1 | 본문 |
| `#667085` / `#FFFFFF` | 약 4.97:1 | 보조 글자 |
| `#667085` / `#F5F7FA` | 약 4.64:1 | 보조 배경 위 글자 |
| `#166534` / `#F0FDF4` | 약 6.81:1 | Do 텍스트 |
| `#991B1B` / `#FEF2F2` | 약 7.60:1 | Don’t 텍스트 |

일반 텍스트 4.5:1, 큰 텍스트 3:1 이상을 만족해야 한다. 필수 UI 구성요소 경계·상태와 의미 있는 그래픽은 해당 비텍스트 대비 기준도 점검한다. `line`은 옅은 장식선이므로 체크박스·입력창의 유일한 식별 수단으로 쓰지 않는다.

### 5-3. 다크·고대비 테마 — 가이드북 추가 확정값

| 역할 | 다크 | 고대비 |
| --- | --- | --- |
| 페이지 배경 | `#101322` | `#000000` |
| 카드·보조 면 | `#1B2030` | `#000000` |
| 제목·본문 | `#F3F5F8` | `#FFFFFF` |
| 보조 글자 | `#B8C2D1` | `#FFFFFF` |
| 링크·주 버튼 배경 | `#8CBDF0` | `#8CBDF0` |
| 주 버튼 글자 | `#101322` | `#000000` |
| 기능 경계 | `#B8C2D1` | `#FFFFFF` |
| 초점 바깥 테두리 | `#FFE66D` | `#FFE66D` |

다크의 링크 `#8CBDF0` / 배경 `#101322`는 약 9.36:1이다. 다크 보조 글자 `#B8C2D1` / 카드 `#1B2030`는 약 9.01:1이다. Do/Don’t는 다크·고대비에서 기본 글자색과 명시적 라벨을 사용하며 필요한 경계를 유지한다. 색상 배경을 무조건 반전하지 않는다.

테마 선택: ‘시스템 설정’, ‘라이트’, ‘다크’, ‘고대비’. 첫 방문은 시스템 설정을 따른다. 사용자가 직접 선택하면 그 설정을 우선 적용한다. OS `forced-colors`를 사용자 정의 고대비 테마와 별도로 지원한다.

| 코드 | 0.9375rem | 400 | 1.7 |

- 루트 크기: 기본은 `100%`. ‘크게’는 `112.5%`, ‘아주 크게’는 `125%`.
- 본문은 일반적인 루트 16px 환경에서 18px, 약 20.25px, 22.5px가 된다. 사용자 브라우저 기본 글자 크기를 존중한다.
- 크기·너비·여백은 rem과 유동 단위를 중심으로 사용한다. `clamp()`의 상·하한도 rem을 포함한다.
- `word-break: keep-all; overflow-wrap: anywhere;`로 한국어를 읽기 쉽게 유지하면서 긴 URL·영문·코드를 처리한다.
- 과한 음수 자간은 사용하지 않는다. 본문은 기본 자간 0.
- 중요 텍스트를 12px 이하로 줄여 배치하지 않는다.
- 공식 배포 서체와 라이선스를 확인해 로컬 제공하고 `font-display: swap`을 사용한다. 서체 로딩 실패 시에도 읽을 수 있어야 한다.

### 5-5. 여백·둥글기·그림자

- 간격 스케일: 4·8·12·16·24·32·48·64px에 해당하는 rem 단위
- 문단 간격: 1.25rem
- H2 앞 간격: 3rem, 뒤 간격: 1rem
- 카드 안쪽: 데스크톱 1.5rem, 모바일 1rem
- 버튼 radius: 12px, 비교·콜아웃 카드 16px, 홈 장 카드 20px
- 카드 그림자는 기본적으로 없음. 떠 있는 패널만 약한 그림자와 경계 사용
- hover 움직임은 필수로 사용하지 않는다. 상태는 색상·밑줄·경계로 전달
- 대형 홍보 페이지의 100px 이상 섹션 여백은 문서 본문에 반복하지 않는다.

## 6. 레이아웃과 탐색

### 데스크톱: 1280px 이상

- 전체 컨테이너 최대 1360px, 좌우 기본 padding 32px
- 왼쪽 전체 목차 232px, 중앙 `minmax(0, 1fr)`, 오른쪽 현재 장 목차 192px
- 열 사이 gap 32px, 본문 자체 최대 760px
- 상단 유틸리티 바: ‘시공간 홈페이지’ 링크, 접근성 설정
- 문서 헤더: 시공간 로고/이름, ‘웹 접근성 실무 가이드’, 검색 링크
- 상단 두 영역의 기본 최소 높이 합계 96px. 텍스트 확대 시 높이 증가를 허용한다.
- 데스크톱 목차는 sticky. 고정 높이로 내용이 잘리지 않도록 max-height와 필요한 내부 스크롤을 사용한다.
- `ResizeObserver` 등으로 실제 헤더 높이를 측정해 `--header-offset`에 반영한다. `scroll-margin-top`·sticky top은 이 값을 공유한다.

### 태블릿: 900~1279px

- 왼쪽 전체 목차와 본문 2열
- 오른쪽 목차는 숨기고 본문 상단에 ‘이 장의 내용’ 접기·펼치기로 제공
- 본문 좌우 padding 24px

### 모바일·확대 환경: 900px 미만

- 본문 1열, 좌우 padding 20px
- 헤더의 ‘전체 목차’ 버튼으로 접기·펼치기 목록을 연다.
- 기본 구현은 본문 위에 삽입되는 비모달 disclosure다. 포커스를 가두거나 본문을 inert 처리하지 않는다.
- 버튼에 `aria-expanded`, `aria-controls` 제공. 닫을 때 숨겨질 영역 안에 초점이 있으면 토글 버튼으로 복귀시킨다.
- 현재 장 목차는 제목·요약 다음의 `<details>`로 제공한다.
- Do/Don’t는 좋은 예 → 피할 예 순서로 세로 배치한다.
- 가로로 긴 표와 코드만 지역 스크롤을 허용한다. 페이지 전체 가로 스크롤을 만들지 않는다.
- 화면 확대 때도 같은 반응형 규칙으로 재배치한다.

### 상세 페이지 읽기 순서

본문 바로가기 → 헤더 → 전체 목차 → breadcrumb → 문서 제목 → 장 요약 → 기준 확인일 → 현재 장 목차 → 본문 → FAQ → 출처 → 에이택 관련 안내(해당 장만) → 이전/다음 장 → 푸터.

CSS 3열 배치가 이 DOM 순서를 의미 없이 바꾸지 않도록 한다. 시각적 오른쪽 목차는 DOM상 본문 안내 위치와 읽기 흐름을 검토해 배치한다.

### 코드 예시의 안전한 표시

나쁜 예의 HTML은 실행하는 예제가 아니라 코드 문자열이다. `alt=""`를 빠뜨린 예시가 가이드 페이지 자체의 실제 이미지로 렌더링되면 안 된다. MDX의 `<img>`·`<svg>`·`<button>` 예시는 모두 fenced code block 또는 escape된 문자열로 처리한다.

### 표의 처리 계약

일반 Markdown table이 항상 원하는 caption과 scope를 생성한다고 가정하지 않는다. 표는 MDX 컴포넌트로 변환한다.

```ts
type TableData = {
  caption: string;
  summary: string;
  columns: { key: string; label: string }[];
  rows: Record<string, string>[];
  rowHeaderKey?: string;
};
```

- summary를 표 직전에, caption을 실제 `<table>` 안에 출력한다.
- 모든 열 제목은 `<th scope="col">`로 출력한다.
- 행을 식별하는 첫 셀이 헤더 역할이면 `<th scope="row">`를 사용한다.
- 데이터는 `<td>`로 출력한다. 불필요한 병합은 피한다.
- 표와 동등한 본문 설명을 유지한다. 두 내용의 수치가 바뀌면 함께 갱신한다.
- overflow가 생기는 wrapper는 접근 가능한 이름을 부여하고 필요한 경우 키보드로 스크롤 가능하게 한다. 모든 작은 표를 무조건 추가 tab stop으로 만들지 않는다.
- 모바일에서 table·tr·td를 block 카드로 강제 변경해 표 관계를 손상시키지 않는다.
- caption이 길면 별도 요약과 구분해 제목은 간결하게 쓴다.

### 코드 복사

Clipboard API는 사용자 클릭 시 실행한다. 성공하면 `role="status"`의 짧은 메시지로 ‘코드를 복사했습니다’를 전달한다. 실패 시 코드를 직접 선택할 수 있도록 안내한다. 알림 후 복사 버튼 초점을 유지하고 본문은 변경하지 않는다.

### 체크리스트

체크박스의 수행 상태는 이 사용자의 점검 기록일 뿐 인증 판정이 아니다. 1차는 페이지 내 임시 상태로 구현하고 새로고침 시 초기화된다고 안내한다. 이행 기록 저장·PDF 내보내기는 별도 요구가 생겼을 때 확장한다. 원문의 ‘공통 발행 점검’은 공개 체크리스트로 자동 전환하지 않는다.

## 8. 검색과 설정

### 검색 — 1차 확정

정적 소규모 문서에 맞춰 빌드 시 검색 인덱스를 생성하고 브라우저에서 검색한다. 별도 검색 서버·계정·API 키는 사용하지 않는다.

- 기본 UI는 `/ko/guide/search/?q=대체텍스트`의 일반 검색 페이지다.
- 헤더 검색은 해당 페이지로 가는 일반 링크다. 1차에 Cmd+K 모달이나 단일 문자 단축키를 추가하지 않는다.
- form은 GET, 입력에 보이는 label과 검색 버튼을 제공한다.
- 검색 인덱스는 장 제목·섹션 제목·해당 본문·섹션 URL을 포함한다. MDX 원문 정규식 삭제보다 빌드 후 렌더링된 콘텐츠의 의미 있는 텍스트를 사용한다.
- 공백·대소문자와 Unicode를 정규화하고 한국어 부분 문자열을 검색한다. 검색어 토큰은 AND로 매칭한다.
- 간단한 동의어 사전: alt ↔ 대체텍스트 ↔ 대체 텍스트, WA ↔ 웹 접근성 인증. 매칭 규칙은 테스트한다.
- 점수: 장 제목 > 섹션 제목 > 본문. 결과는 섹션 URL과 문맥 일부를 보여준다.
- 결과 개수는 `role="status" aria-live="polite"`로 전달한다. 키 입력마다 과하게 알리지 않도록 제출 시 또는 debounce 후 갱신한다.
- 결과 없음: 검색어를 보존하고 ‘대체텍스트’, ‘키보드’, ‘WA 인증’ 등 실제 검색어와 전체 목차를 제공한다.
- 결과 하이라이트는 DOM의 text node와 `<mark>`를 이용한다. 검색어를 `innerHTML`로 삽입하지 않는다.
- JavaScript가 없으면 검색 의존성을 짧게 알리고 전체 6개 장 링크를 제공한다. 본문과 목차는 계속 이용 가능해야 한다.

콘텐츠가 수십·수백 장으로 커지면 Pagefind 등 빌드형 검색으로 확장할 수 있다. 1차 범위에서는 별도 라이브러리 없이 위 검색 계약을 구현한다.

### 설정

- `themePreference`: system / light / dark / high-contrast
- `textSize`: normal / large / xlarge
- 저장 키: `sigongan-guide-preferences-v1`
- localStorage 읽기·쓰기 실패 시도 오류 없이 기본값으로 동작한다.
- 저장값은 허용된 값만 적용한다. JSON parse 실패를 처리한다.
- ‘설정 초기화’는 이 키만 삭제하고 다른 사이트 저장소를 건드리지 않는다.
- 시스템 설정 선택 중에는 OS 테마 변경을 반영한다. 명시적 사용자 선택을 시스템 변경으로 덮지 않는다.
- 설정 UI가 없어도 OS·브라우저 확대, 기본 글자 크기, forced-colors가 동작해야 한다.
- 테마 초기 적용은 초기 paint 전에 최소 스크립트로 수행하되 문서 렌더링을 막는 대형 번들을 추가하지 않는다.
- 초기 HTML은 설정 버튼 없이도 읽을 수 있게 한다. JS 초기화 후 조작 가능한 설정을 노출한다.

## 9. 접근성 구현 기준

목표는 KWCAG 2.2와 WCAG 2.2 A·AA를 각각 충족하도록 구현하고 검증하는 것이다. 개발 완료나 자동 점수만으로 ‘완벽 준수’, ‘인증 완료’를 표시하지 않는다.

### 시맨틱과 문서 구조

- `<html lang="ko">`, 고유한 page title, 페이지당 H1 하나
- `<header>`, 이름 있는 `<nav>`, `<main id="main">`, `<article>`, `<footer>` 사용
- 반복되는 nav에는 ‘전체 가이드 목차’, ‘이 장의 내용’, ‘이전 다음 장’처럼 구별되는 이름 제공
- 첫 Tab에서 보이는 ‘본문으로 건너뛰기’ 링크 제공
- main 또는 대상 제목에 필요 시 `tabindex="-1"`를 주어 skip·앵커 이동을 검증
- 링크는 이동, 버튼은 동작. native HTML을 우선하고 불필요한 ARIA를 추가하지 않음
- `tabindex` 양수 사용 금지
- 소제목 링크는 hover에서만 보이는 유일한 컨트롤로 만들지 않음
- 사용자에게 보이는 레이블과 accessible name의 일치 확인

### 키보드와 초점

- 모든 조작은 키보드로 가능해야 한다.
- `:focus-visible`은 최소 3px의 명확한 외곽선과 3px offset을 사용한다. 수치는 이 프로젝트 설계값이다.
- 밝은 배경에서는 브랜드 블루, 어두운 배경·버튼 위에서는 밝은 링과 필요한 이중 링을 사용해 구분한다.
- overflow 영역이 초점 링을 잘라내지 않도록 한다.
- sticky 헤더가 키보드 초점과 앵커 제목을 가리지 않도록 실제 높이에 기반해 offset을 준다.
- hover만으로 열리는 정보·메뉴를 만들지 않는다.
- 1차 설정·모바일 목차는 비모달 disclosure로 구현한다. 이후 모달로 바꾸면 APG에 따라 초기 초점·Tab 순환·Escape·초점 복귀·배경 inert를 모두 구현한다.
- 좁은 화면 목차를 열고 닫을 때만 필요한 초점 처리를 한다. 스크롤 감지로 본문 초점을 이동하지 않는다.

### 명도 대비와 상태

- 일반 텍스트 최소 4.5:1, 큰 텍스트 최소 3:1
- 의미 있는 컨트롤·상태·그래픽은 해당 3:1 기준 및 예외를 검토
- 본문 링크는 기본 밑줄을 사용해 색상만으로 구분하지 않음
- 현재 목차는 블루 배경 + 굵기 + 세로 표시 + aria-current로 구분
- 문서 카드는 마우스 hover 외에도 keyboard focus 상태 제공
- 모든 테마·hover·focus·visited·오류·선택 상태를 확인
- 정적 콜아웃을 alert로 읽게 만들지 않음

### 크기와 재배치

- 주요 버튼·아이콘 버튼의 터치 영역은 최소 44×44 CSS px를 프로젝트 기준으로 한다.
- WCAG 2.2 AA의 2.5.8 최소 타깃 기준은 원칙적으로 24×24 CSS px이며 예외가 있다. 프로젝트의 44px 규칙과 구분한다.
- 문장 속 인라인 링크까지 일괄 44px 높이로 만들지 않는다.
- 200% 텍스트 확대와 400% 브라우저 확대를 각각 확인한다.
- 320 CSS px 너비에서 본문 정보·기능 손실과 페이지 전체 가로 스크롤이 없어야 한다. 데이터 표 등 본질적 2차원 콘텐츠는 지역 스크롤로 처리한다.
- 사용자 text spacing 변경: 행간 1.5배, 문단 뒤 2배, 자간 0.12em, 단어 간격 0.16em에서도 잘림·겹침을 확인한다. 이는 기본 디자인을 해당 값으로 만들라는 뜻이 아니다.
- 버튼·탐색·카드는 고정 height보다 min-height를 사용해 텍스트 증가를 수용한다.
- 확대를 막는 `maximum-scale=1`, `user-scalable=no`를 사용하지 않는다.

### 움직임·OS·이미지

- `prefers-reduced-motion: reduce`에서 부드러운 스크롤과 장식 전환을 제거한다.
- 필수 정보에 입장 애니메이션, 스크롤 리빌, 캐러셀을 사용하지 않는다.
- Windows forced-colors 환경에서 경계·초점·선택 상태를 확인한다. 광범위한 `forced-color-adjust: none` 금지.
- 정보 이미지에 문맥에 맞는 alt, 장식에 빈 alt 적용
- ‘시공간’ 텍스트가 함께 있는 로고는 중복 낭독을 줄이고, 링크 전체 이름이 회사 홈을 가리키도록 한다.
- 공식 로고 파일은 현재 페이지에서 `/logos/sigongan.png`, 에이택 로고는 `/logos/aitag.png` 경로를 관찰했다. 실제 배포물에는 권한 있는 원본을 로컬 자산으로 포함한다. 원본 미확보 상태에서는 시공간 텍스트 로고를 쓰고 로고를 임의로 그리지 않는다.

## 10. 기술 스택과 폴더 구조

### 권장 스택 — 확정

Astro + TypeScript + MDX + CSS custom properties + 필요한 소량의 브라우저 JavaScript. 정적 output을 사용한다.

6개 장의 읽기 중심 사이트여서 서버 렌더링·DB·로그인이 필요하지 않다. Astro는 Markdown/MDX 중심의 정적 페이지를 만들고 Vercel에 배포하는 흐름을 지원한다. React·Next.js는 향후 앱 기능이 필요한 경우에 재검토하며 1차 필수 의존성으로 추가하지 않는다.

Astro·MDX·TypeScript의 실제 버전은 구현 시점의 상호 호환되는 안정 버전을 선택하고 lockfile에 고정한다. 문서에 적혀 있지 않은 예전 Content Collections API를 추측해서 사용하지 않는다.

### 빌드와 배포

- 정적 output, 기본 산출물 `dist/`
- 빌드: 콘텐츠 검증 → Astro check → Astro build → 검색 인덱스 생성·검증
- package scripts에 `check`, `build`, `preview`, `test` 제공
- Vercel의 Astro preset을 우선 사용한다. 정적 사이트에 불필요한 SSR adapter를 추가하지 않는다.
- preview deployment에서 deep link·앵커·404·검색을 확인한다.
- root redirect만 설정하고 모든 URL을 한 페이지로 보내는 광범위 SPA rewrite는 넣지 않는다.
- 사이트 URL은 환경별로 설정하고, 확정 전 회사 도메인 경로를 canonical로 꾸며 쓰지 않는다.
- 운영 도메인 확정 후 canonical·sitemap·OG URL·robots를 점검한다.
- 외부 광고·추적 스크립트, 계정, DB, 이메일 수집은 1차 범위에 넣지 않는다.
- 배포 방법과 실제 실행 명령을 README에 기록한다. 이 문서만으로 이미 배포되었다고 보고하지 않는다.

### 인쇄

브라우저 인쇄에서는 헤더·양쪽 목차·설정·복사 버튼을 숨기고 본문·출처를 출력한다. 배경색 없이도 Do/Don’t 라벨과 코드·표를 이해할 수 있어야 한다. 인쇄 기능을 PDF 다운로드 서비스가 준비된 것처럼 표시하지 않는다.

## 11. 구현 순서와 완료 기준

### 순서

1. 현재 저장소와 AGENTS.md·기존 개발 규칙을 확인한다.
2. 입력 문안 6개 장을 분리하고 제목·출처·앵커·브랜드 표기를 검증한다.
3. 색상·타이포그래피·레이아웃·반응형 규칙을 구현한다.
4. Do/Don’t·표·코드·체크리스트를 실제 콘텐츠에 적용한다.
5. 목차·검색·설정·복사 기능을 구현한다.
6. 자동 점검과 수동 이용 검증을 수행하고 문제를 수정한다.
7. Vercel 배포 가능한 소스와 실행 안내·검증 결과를 제공한다. 실제 배포 작업은 권한과 사용자 요청 범위에 따른다.

### 필수 확인 시나리오

| 범위 | 검증 | 통과 기준 |
| --- | --- | --- |
| 콘텐츠 | 6개 장·예시·FAQ·출처 비교 | 누락·임의 요약·브랜드 뒤바뀜 없음 |
| 경로 | 각 장 직접 접속·새로고침·404 | 의도한 페이지 렌더링 |
| 전체 탐색 | 키보드로 홈→3장→5장→이전·다음 | 초점 순서·현재 위치·실제 링크 정상 |
| 앵커 | 3장 7원칙 링크·deep link | 대상 제목 표시, 헤더에 가리지 않음 |
| 검색 | ‘대체텍스트’, ‘alt’, ‘WA 인증’, 없는 검색어 | 관련 섹션 링크·결과 없음·상태 안내 정상 |
| 설정 | 테마·글자 크기 선택→새로고침→초기화 | 사용자 설정 우선·정상 복원·초기화 |
| 내결함성 | 저장소 접근 차단·JS 비활성 | 본문·목차·링크는 계속 이용 가능 |
| 반응형 | 1440·1024·900·899·390·320 CSS px | 목차 전환·비교 카드·표 정상, 페이지 넘침 없음 |
| 확대 | 200% text resize, 400% browser zoom | 정보·기능 손실, 초점 가림 없음 |
| 표 | 스크린리더 표 탐색 | caption·행열 제목·값 관계 인지 가능 |
| 코드 | 나쁜 예 HTML 표시·복사 성공·실패 | 예시가 실행되지 않고 코드로 표시됨 |
| 테마 | 라이트·다크·고대비·forced-colors | 글자·링크·초점·선택 상태 식별 가능 |
| 인쇄 | 브라우저 print preview | 본문·표·출처 보존, UI 겹침 없음 |

### 테스트 방식

- 자동: Astro check·빌드·콘텐츠 무결성 검사, 대표 페이지 axe 등 접근성 자동 검사
- 브라우저: Playwright 등으로 의미 있는 경로·검색·설정·메뉴 동작 검증
- 수동: 키보드 전 과정, NVDA+Chrome 또는 Firefox, VoiceOver+Safari, 모바일 TalkBack+Chrome 등 대표 조합 확인
- 수동 검증이 가능한 환경만 수행하고, 수행하지 못한 OS·보조기술은 ‘미실시’로 명확하게 기록
- Lighthouse 점수 100 또는 axe 오류 0을 WCAG 전체 준수나 WA 인증과 동일하게 표현하지 않음
- 결과는 환경·버전·대상 URL·문제·수정·재검증·미실시 항목을 포함해 `docs/review-log.md`에 기록

### 개발을 막지 않는 운영 확인 사항

- 최종 공개 도메인: 미정. Vercel 기본 주소와 설정값으로 먼저 구현 가능.
- 회사 사이트 메뉴에 가이드 링크 추가·경로 통합: 운영 권한과 배포 구조 확인 후 연결.
- 공식 로고 원본·서체 파일: 확인 후 포함. 없으면 텍스트 로고·fallback으로 구현 가능.
- PDF 제공·상담 폼: 별도 요구 전에는 기존 실제 에이택 링크만 사용.
- 실제 보조기술·실기기 테스트와 인증: 구현 이후 수행. 현재는 사양 및 단색 대비 계산만 완료.
